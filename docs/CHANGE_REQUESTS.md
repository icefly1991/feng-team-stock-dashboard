# Change Requests

> 当已确认需求需要改变时，不直接删除或覆盖旧需求。先建立 Change Request，记录原需求、新需求、原因和影响。

## 编号规则

- 正式变更：`CR-001`、`CR-002`、`CR-003`
- 示例或教学用途：使用显式标记，如 `CR-EXAMPLE`

## 状态说明

- `Draft`
- `Proposed`
- `Accepted`
- `Implemented`
- `Rejected`
- `Deferred`
- `Cancelled`

## 使用模板

```markdown
## CR-001：变更标题

- 状态：Proposed
- 提出日期：YYYY-MM-DD
- 决定日期：
- 提出人：
- 关联原需求：UI-xxx
- 关联新需求：
- 关联决策：ADR-xxx

### 原需求

原来的正式要求。

### 新需求

准备修改成什么。

### 修改原因

为什么要修改。

### 影响分析

#### 数据影响

是否改变字段、公式、数据源或历史数据。

#### 前端影响

是否改变布局、排序、交互或响应式行为。

#### 后端或脚本影响

是否改变 Python、API 或数据生成。

#### 部署影响

是否影响 GitHub Actions 或 GitHub Pages。

#### 兼容性影响

是否影响旧数据、旧链接或旧浏览器。

#### 测试影响

需要增加或修改哪些测试。

### 风险

列出可能的负面结果。

### 验收标准

- [ ] 条件一
- [ ] 条件二

### 决定

接受、拒绝或延期的原因。

### 实施记录

实施日期、提交记录和结果。
```

## 示例，不是当前已确认变更

### CR-EXAMPLE：取消移动端固定股票列

- 状态：Draft
- 提出日期：2026-07-22
- 决定日期：
- 提出人：示例
- 关联原需求：UI-002
- 关联新需求：
- 关联决策：ADR-004

### 原需求

移动端表格通过固定左侧关键列提高名称、代码与排名的可读性。

### 新需求

取消移动端固定股票列，改为整个表格统一横向滚动。

### 修改原因

固定列可能占用过多横向空间，影响小屏幕设备上的可视宽度。

### 影响分析

#### 数据影响

无。该变更不改变指标公式、字段或数据源。

#### 前端影响

会改变移动端表格滚动体验、左侧层级和 sticky 行为。

#### 后端或脚本影响

无。Python 数据生成逻辑不受影响。

#### 部署影响

无直接部署影响。

#### 兼容性影响

旧数据兼容性不受影响，但用户习惯可能发生变化。

#### 测试影响

需要重新验证移动端布局、横向滚动、表头对齐和主要信息可读性。

### 风险

- 取消固定列后，横向滚动时股票身份识别变慢
- 移动端扫描效率下降

### 验收标准

- [ ] 小屏幕下可用宽度明显改善
- [ ] 取消固定列后仍能快速识别当前行股票

### 决定

示例，不代表当前项目已接受该变更。

### 实施记录

无。该条目仅用于说明记录方式。
