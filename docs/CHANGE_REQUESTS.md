- 决定日期：2026-09-16
- 提出人：项目用户

- 关联新需求：DATA-013, UI-015

### 原需求

最近两个完整年度归母净利润为正，页面仅展示最新年度利润。

### 新需求与决定

接受用户要求：最近三个完整年度归母净利润分别严格大于 0，且最新已披露正式财报的累计归母净利润大于等于 0。用户已明确选择累计财报口径。当前对应 2023、2024、2025 年；最新财报按报告期选择，不使用预告或快报。页面增加最新财报报告期、披露日期和累计归母净利润；手机可在股票下展开“最新财报”查看完整信息。

### 影响分析

总市值严格低于 25 亿元及升序规则不变。一次 income 查询同时获取三年及最新财报；仅使用合并累计报表，以生成日（北京时间）为披露截止日，同期取最新披露版本、同日优先更新标志。最新期亏损或数值缺失时不得回退至之前盈利期。新增筛选元数据、最新财报字段和独立阶段数量；前端拒绝旧两年规则数据。新增一列并验证桌面和手机横向滚动。

### 验收标准

- [x] 三年逐年严格盈利，最新期零利润通过、负值或缺失不通过
- [x] 正确选择报告期和修订版本，排除未来披露、单季和母公司报表
- [x] 真实重新生成、页面显示最新财报依据、各阶段数量一致
- [x] 单元测试、静态检查、构建和桌面/手机模拟验证通过

### 实施与验证记录

2026-09-16：真实重算 223 只市值候选，99 只连续三年盈利、74 只最新财报不亏损，最终展示 74 只，生成错误为 0，比上一版 108 只减少 34 只。独立从 223 只原始 income 响应重算名单与三年/最新利润，完全一致；入选最新报告期均为 20260630。

14 项单元测试、ESLint、生产构建通过。Chrome 验证全部 74 行排序、财报金额/报告期/日期、搜索、复制、异常数据拒绝、主页回归；1280px 桌面及 390px、320px 手机模拟视口验证通过，手机展开财报完整可读，表头滚动同步。未做手机真机验证；财报及时性依赖 Tushare 数据入库。

修改文件：`scripts/generate_growth_market_dashboard.py`（三年及最新报表筛选）、`src/GrowthMarketPage.tsx`（规则、阶段数量、最新财报展示及旧数据校验）、`public/data/growth-market-dashboard.json`（真实数据）、`tests/test_growth_market_dashboard.py`（财报边界与版本选择测试）；`PROJECT_RULES.md`、`README.md`、`docs/REQUIREMENTS.md`、`docs/metric-definitions.md`、`docs/CHANGE_REQUESTS.md`、`docs/CHANGELOG.md` 同步口径和验证记录。

## CR-003：股票池市值口径改为总市值

- 状态：Implemented
- 提出日期：2026-09-16
- 决定日期：2026-09-16
- 提出人：项目用户
- 关联原需求：DATA-008, UI-007, UI-011
- 关联新需求：DATA-012, UI-014
- 关联决策：ADR-001, ADR-003, ADR-004

### 原需求

股票池使用 `daily_basic.circ_mv` 筛选流通市值低于 20 亿元的股票，页面展示流通市值。当前榜单实际按 UI-011 的 52 周内位置升序排列。

### 新需求

- 使用 `daily_basic.total_mv` 筛选总市值严格低于 20 亿元的股票，单位从万元换算为亿元
- Python、JSON、前端市值列、筛选说明与当前规则文档统一使用总市值
- 重新拉取真实数据生成股票池，禁止把旧流通市值数值改名当作总市值
- 按本次“筛选和排序全部换成总市值”的要求，榜单改为总市值升序，同值按股票代码升序；搜索结果遵循相同规则

### 影响分析

- 股票池成员及各筛选阶段数量会改变；两年盈利、非 ST、上市天数及价格指标计算口径不变
- 新字段为 `total_market_cap_yi` 和 `total_market_cap_lt_yi`，旧 JSON 不兼容，前端需明确识别旧数据
- 原部署工作流继续运行同一数据脚本，不变更自动部署机制
- 验证总市值与流通市值不同的样例、20 亿元边界、无效数据、真实重新生成、搜索与复制交互

### 决定

接受。用户明确要求股票池相关逻辑使用总市值，替代原流通市值口径。

### 实施记录

2026-09-16：完成 DATA-012 / UI-014，数据源改为 `total_mv`、字段与界面改为总市值、数据及页面按总市值升序；按 2026-09-15 行情重新生成 37 只股票，独立查询核对总市值一致。7 项 Python 测试、ESLint、生产构建和桌面/手机浏览器验证通过。旧口径保留在历史文档中，旧 JSON 不能作为新口径输入使用。

## CR-001：新股票池只展示最新年度利润并增加主营业务

- 状态：Implemented
- 提出日期：2026-08-23
- 决定日期：2026-08-23
- 提出人：项目用户
- 关联原需求：UI-007, DATA-008
- 关联新需求：
- 关联决策：ADR-001, ADR-004

### 原需求

新股票池页面同时展示最近两个完整年度的归母净利润。

### 新需求

- 最近两个完整年度归母净利润均为正的筛选规则保持不变
- 页面只展示最新完整年度归母净利润
- 页面新增公司主营业务摘要，数据来自 Tushare `stock_company.main_business`
- 搜索同时匹配股票名称、代码和主营业务

### 修改原因

减少表格中重复的利润列，将空间用于帮助用户理解公司的主要业务。

### 影响分析

#### 数据影响

保留两年利润供筛选与追溯，新增 `main_business` 字段，不改变盈利筛选公式。

#### 前端影响

#### 部署影响

不改变部署入口，仅增加少量数据请求与 JSON 体积。

#### 兼容性影响

旧 JSON 缺少 `main_business` 时需要重新生成数据后才能完整展示。

#### 测试影响

验证接口权限、主营业务覆盖率、搜索、表头对齐和生产构建。

### 风险

- 主营业务文字较长，移动端需要横向滚动
- 个别公司可能缺少主营业务字段

### 验收标准

- [x] 页面只展示最新完整年度利润
- [x] 两年盈利筛选规则未改变
- [x] 页面展示主营业务并支持搜索
- [x] 主营业务接口可以批量访问

### 决定

接受。展示信息减少但筛选依据保持不变，新增主营业务能提高股票池可理解性。

### 实施记录

2026-08-23 完成数据字段、页面列和搜索逻辑修改。

- 决定日期：
- 提出人：示例

固定列可能占用过多横向空间，影响小屏幕设备上的可视宽度。

无。该变更不改变指标公式、字段或数据源。

#### 测试影响

需要重新验证移动端布局、横向滚动、表头对齐和主要信息可读性。

- 取消固定列后，横向滚动时股票身份识别变慢
- 移动端扫描效率下降
