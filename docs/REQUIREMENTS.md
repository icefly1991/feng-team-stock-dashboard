# Requirements

> 聊天记录、临时想法和 AI 对话不自动构成正式需求。只有进入本文件并分配编号的内容，才视为项目需求。

## 编号规则

- `DATA-xxx`：数据和指标
- `UI-xxx`：界面和交互
- `OPS-xxx`：自动化、部署和运维
- `NFR-xxx`：性能、稳定性、兼容性
- `REQ-xxx`：无法归类的一般需求

## 状态说明

- `Draft`
- `Proposed`
- `Accepted`
- `In Progress`
- `Implemented`
- `Superseded`
- `Deprecated`
- `Rejected`
- `Deferred`

## 优先级说明

- `P0`：必须完成或影响核心正确性
- `P1`：重要
- `P2`：一般改进
- `P3`：可选

## DATA-007：52 周内位置

- 状态：Implemented
- 优先级：P1
- 创建日期：2026-08-23
- 最后更新：2026-08-23
- 关联决策：ADR-003
- 关联变更：

### 需求

- 使用最近 `252` 个交易日最高 `high` 与最低 `low` 确定价格区间
- 按 `(当前收盘价 - 最低 low) / (最高 high - 最低 low) * 100` 计算线性位置
- `0%` 表示区间低点，`100%` 表示区间高点；该指标不表示时间或历史路径进度
- `qfq` 与 `none` 必须独立计算，榜单按数值从大到小排列

### 验收标准

- [x] 输出字段为 `position_52w_pct`
- [x] 最高点和最低点取自同一复权口径、同一 252 日窗口
- [x] 高低点相等时不伪装成有效数值
- [x] 前端提供“52周内位置”选项并按降序排列

- 状态：Implemented
- 优先级：P1
- 创建日期：2026-08-23
- 最后更新：2026-08-23
- 关联决策：ADR-004
- 关联变更：

### 背景

Growth 股票池记录较多，用户纵向浏览到页面下方后仍需要识别各数据列含义。

### 需求

- Growth 榜单表头在页面纵向滚动时保持悬浮可见
- 悬浮表头必须使用不透明度足够的背景、分隔线和克制的阴影，避免与下方数据混叠
- 横向滚动时表头必须与数据列同步移动并保持对齐
- 不改变股票数据字段、排序或筛选口径

### 验收标准

- [x] 表头使用 sticky 定位并保持在榜单顶部
- [x] 表头层级高于数据行
- [x] 表头与数据行使用完全相同的网格列定义
- [x] 移动端仍可横向滚动查看全部列
